# AivibeBoard

Одностраничная доска задач (аналог Trello / лёгкой Jira) с лендингом, входом через Supabase, несколькими канбан-досками на аккаунт, ИИ-разбиением эпиков, inbox Telegram и базой знаний по проекту.

Приложение открывается на лендинге. После входа или регистрации пользователь попадает на **«Мои доски»**, а не сразу на канбан. У каждой доски свои колонки и задачи; **команда**, **база знаний**, **Telegram** и **настройки проекта** общие для браузера (IndexedDB).

## Где что хранится

| Данные | Хранилище | Синхронизация |
|--------|-----------|----------------|
| Сессия (вход) | Supabase Auth | Между устройствами |
| Доски, колонки, задачи | Supabase Postgres (`boards`, `board_columns`, `board_tasks`) | В облаке под `owner_id = auth.uid()` |
| Команда, знания, Telegram, настройки | IndexedDB (`src/services/storage.ts`) | Только этот браузер |

`memberIds` на доске — это id участников из **локальной команды** (метаданные на карточке; отдельных аккаунтов у них нет).

При первом входе после обновления приложение один раз копирует доски из IndexedDB в Supabase (если в облаке пусто), затем ставит флаг `localStorage` → `aivibeboard.migratedBoards = 1`. Для нового пользователя без досок создаётся демо-доска «Демо» в Supabase.

### Схема Supabase

SQL-миграция в репозитории: [supabase/migrations/20261109170318_create_boards_kanban.sql](./supabase/migrations/20261109170318_create_boards_kanban.sql).

На новом проекте Supabase выполните этот скрипт в SQL Editor (или через Supabase CLI). Включён **RLS**: чтение и запись только для владельца доски. Удаление доски каскадом снимает колонки и задачи.

Клиент: `src/services/boardRemote.ts`, сообщения об ошибках — `src/services/boardErrors.ts`.

## Языки

Интерфейс: **русский, английский и иврит**. Переключатель **RU | EN | עב** стоит в шапке лендинга, формы входа и доски. Выбор пишется в `localStorage` (`aivibeboard.locale`) и переживает перезагрузку.

Для иврита у `<html>` выставляются `lang="he"` и `dir="rtl"`: вёрстка зеркалится, жёлтая полоска лендинга уезжает на правый край.

Переводится chrome UI и сообщения об ошибках. Названия колонок, задач и прочие пользовательские данные остаются как есть.

Словари и провайдер: `src/i18n/`.

## Переменные окружения

Скопируйте `.env.example` в `.env` (файл `.env` в git не попадает):

```env
VITE_OPENAI_API_KEY=
VITE_OPENAI_MODEL=gpt-4o-mini
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

| Переменная | Назначение |
|------------|------------|
| `VITE_SUPABASE_URL` | URL проекта Supabase. Обязателен для входа и досок. |
| `VITE_SUPABASE_ANON_KEY` | Публичный anon-ключ. Обязателен. Не путайте с `service_role`. |
| `VITE_OPENAI_API_KEY` | Ключ для «ИИ-постановки». Пустое значение включает локальный fallback. |
| `VITE_OPENAI_MODEL` | Модель OpenAI. По умолчанию в примере — `gpt-4o-mini`. |

Без ключа OpenAI раздел «ИИ-постановка» разбивает текст локально: по строкам и пунктам.

**Важно:** значения `VITE_*` попадают в бандл браузера. Anon-ключ Supabase для этого и рассчитан (доступ ограничивают политики RLS). Ключ OpenAI в продакшене лучше прятать за прокси (см. Roadmap).

### Supabase Auth

В проекте Supabase включите Email provider. Приложение использует только email и пароль:

- вход — `signInWithPassword`;
- регистрация — `signUp`, пароль от 6 символов, ссылка подтверждения ведёт на `window.location.origin`;
- выход — кнопка «Выйти» в шапке доски.

Если в проекте включено подтверждение email, после регистрации сессии ещё нет: на форме появится просьба открыть письмо. После перехода по ссылке приложение откроет рабочую зону.

В настройках Auth добавьте адрес приложения (для локальной разработки обычно `http://localhost:5173`) в **Site URL** и **Redirect URLs**.

## Экраны

1. **Лендинг** (`LandingPage`) — возможности, шаги и призыв к действию. Если сессия уже есть, кнопки ведут в приложение («Открыть доску»), иначе на форму входа.
2. **Вход и регистрация** (`AuthPage`) — переключение вкладок на одной форме. Ошибки Supabase показываются на выбранном языке.
3. **Мои доски** (`BoardsPage`) — список досок, создание/редактирование в диалоге (`BoardFormModal`), удаление (`BoardDeleteDialog`), открытие канбана.
4. **Канбан** (`AppShell` + `Board`) — рабочее приложение выбранной доски. В шапке ссылка «← Мои доски», кнопка «Сайт» возвращает на лендинг без выхода из аккаунта.

Сессию (лендинг / вход / приложение) держит `useAppSession`. `App.tsx` переключает экраны.

## Разделы канбана

| Раздел | Описание |
|--------|----------|
| Доска | Канбан, drag-and-drop, CRUD задач и колонок (только активная доска) |
| База знаний | Загрузка `.md`, `.txt`, `.pdf` (PDF — ограниченный текст) |
| ИИ-постановка | Эпик → подзадачи с исполнителями; контекст из выбранных документов |
| Telegram | Inbox, симуляция сообщений, создание задач на активной доске |
| Команда | Участники для назначения, ИИ и выбора в форме доски |
| Настройки | Имя проекта, секрет webhook |

## Telegram webhook (будущее)

Контракт тела POST для `ingestTelegramMessage`:

```json
{
  "secret": "ваш-секрет-из-настроек",
  "chatId": "-100123",
  "fromUsername": "user",
  "text": "Текст задачи"
}
```

В MVP ingest вызывается из SPA; для реального бота нужен небольшой сервер, который принимает апдейты Telegram и пересылает payload (или пишет в общее хранилище).
